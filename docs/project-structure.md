# Project Structure

This file explains what each important file and directory does.

## Root Files

`README.md`

Short project entry point with quickstart commands and links to detailed docs.

`pyproject.toml`

Defines the Python package, dependencies, console scripts, and tool
configuration.

Important sections:

- `[project]` contains package metadata and runtime dependencies.
- `[project.optional-dependencies]` contains development dependencies.
- `[project.scripts]` defines installed commands such as `mlops-train`.
- `[tool.ruff]`, `[tool.pytest.ini_options]`, and `[tool.mypy]` configure checks.

`dvc.yaml`

Defines the DVC pipeline. It has two stages:

- `prepare_data`: runs `.venv/bin/python -m mlops_tabular.data`
- `train`: runs `.venv/bin/python -m mlops_tabular.train`

`dvc.lock`

Generated by DVC after `dvc repro`. It records command hashes, dependency
hashes, output hashes, and the exact pipeline state from the latest run.

`Dockerfile`

Builds the inference API image. It starts from `python:3.11-slim`, installs the
package with `pip`, and runs Uvicorn.

`.dockerignore`

Excludes local development files and generated caches from Docker build context.

`.gitignore`

Excludes virtual environments, Python caches, generated data, models, reports,
MLflow runs, and other local-only files.

`.pre-commit-config.yaml`

Defines pre-commit hooks for formatting, YAML checks, Ruff, and mypy.

`.env.example`

Shows optional environment variables that can override default training,
tracking, model path, and logging settings. It does not contain secrets.

`LICENSE`

Declares the project license.

`CONTRIBUTING.md`

Documents local setup, checks, and contribution expectations.

`SECURITY.md`

Documents security notes for model artifacts, secrets, and educational use.

`.dvcignore`

Tells DVC which files to ignore when scanning the workspace.

## Python Package

The application package is `src/mlops_tabular`.

`src/mlops_tabular/__init__.py`

Marks the directory as a Python package and stores `__version__`.

`src/mlops_tabular/config.py`

Centralizes configuration and paths.

Defines:

- `PROJECT_ROOT`
- `DATA_DIR`
- `RAW_DATA_DIR`
- `PROCESSED_DATA_DIR`
- `MODEL_DIR`
- `MODEL_PATH`
- `REPORTS_DIR`
- `METRICS_PATH`
- `Settings`

`Settings` reads optional environment variable overrides:

- `MLOPS_RANDOM_STATE`
- `MLOPS_TEST_SIZE`
- `MLOPS_N_ESTIMATORS`
- `MLFLOW_EXPERIMENT_NAME`
- `MLFLOW_TRACKING_URI`
- `MODEL_PATH`

`src/mlops_tabular/data.py`

Owns dataset preparation.

Main responsibilities:

- Load scikit-learn's breast cancer dataset.
- Normalize feature names to snake case.
- Add numeric target and human-readable target label columns.
- Create train/test splits.
- Write CSV outputs under `data/`.

Run it with:

```bash
.venv/bin/python -m mlops_tabular.data
```

`src/mlops_tabular/train.py`

Owns model training and experiment tracking.

Main responsibilities:

- Load processed train/test CSV files.
- Split features and target columns.
- Build a scikit-learn pipeline.
- Train `RandomForestClassifier`.
- Evaluate accuracy, F1, and ROC AUC.
- Log parameters and metrics to MLflow.
- Save `models/latest/model.skops`.
- Save `reports/metrics.json`.

Run it with:

```bash
.venv/bin/python -m mlops_tabular.train
```

`src/mlops_tabular/model.py`

Owns model loading and prediction logic.

Main responsibilities:

- Load the `skops` model bundle from disk.
- Cache the loaded model for API serving.
- Validate incoming feature names.
- Convert request features to a pandas dataframe.
- Run `predict` and `predict_proba`.
- Return a normalized prediction result.

`src/mlops_tabular/api.py`

Owns the FastAPI service.

Defines:

- `GET /health`
- `POST /predict`
- `GET /metrics`

Also configures JSON logging and provides a `main()` entry point for serving.

`src/mlops_tabular/metrics.py`

Owns Prometheus metrics.

Defines:

- `mlops_tabular_predictions_total`
- `mlops_tabular_prediction_latency_seconds`

The API records these metrics for prediction requests and exposes them through
`GET /metrics`.

## Tests

`tests/test_data.py`

Checks that the demo dataset has the expected schema and that train/test splits
are written correctly.

`tests/test_train.py`

Runs a training smoke test and verifies that model artifacts, metrics, and a
run id are produced. It also checks basic quality thresholds.

`tests/test_api.py`

Tests the FastAPI health and prediction endpoints using the trained model.

## Kubernetes Files

`k8s/kind/cluster.yaml`

Defines the local `kind` cluster. It maps host port `8080` to node port `30080`.

`k8s/base/deployment.yaml`

Defines the API Kubernetes `Deployment`.

Important parts:

- uses image `tabular-mlops-lab:latest`
- sets `MODEL_PATH=/app/models/latest/model.skops`
- exposes container port `8000`
- defines liveness and readiness probes
- defines CPU and memory requests/limits

`k8s/base/service.yaml`

Defines a `NodePort` service for the API.

`k8s/base/kustomization.yaml`

Collects the deployment and service so they can be applied with:

```bash
kubectl apply -k k8s/base
```

## CI

`.github/workflows/ci.yml`

Runs on pull requests and pushes to `main`.

The workflow:

1. Checks out the repository.
2. Sets up Python.
3. Installs dependencies with `pip`.
4. Runs Ruff.
5. Runs mypy.
6. Runs pytest.
7. Runs a training smoke test.
